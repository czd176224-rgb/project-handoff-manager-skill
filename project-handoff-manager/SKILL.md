# 项目管家

## 使用原则

1. 每次先运行 `scripts/project_manager.ps1 -Action menu`，向用户显示四项操作。
2. 任何操作前，先展示将执行的内容、涉及的精确路径和预期结果。
3. 复制、校验和清理必须分阶段执行；校验成功前不得删除源副本。
4. 不读取、不修改、不迁移 Codex 桌面版数据库或对话数据库。
5. 不迁移登录凭据、令牌、Cookie 或系统级软件本体。
6. 项目文件夹实扫结果是事实来源，登记文件只作为索引。

## 四项操作

1. 开始或继续当前项目：对已有文件夹自动补充项目管理结构，读取交接报告并检查环境。
2. 暂停当前项目：先列出可证明属于项目的进程、判定证据、预计释放内存和跳过项；用户明确确认后才停止，并更新交接信息。Codex 主程序、系统保护进程和归属不明进程默认不停止。
3. 将当前项目归还到 T9：先显示磁盘身份、进程、敏感文件、联接点、冲突、源路径、暂存路径、正式路径、文件数和大小；确认后更新交接、缓存和离线依赖清单，完整复制到暂存目录并校验，再提交为正式目录。目标校验成功后仍保留本机来源，只有第二次明确确认且两份摘要均未变化时才清理本机副本。
4. 从 T9 借出项目到本机：先预览 T9 来源、本机暂存和正式路径、磁盘身份、来源与仓库是否确实位于已验证盘符、空间、重解析点和不可读文件；旧项目会明确显示“借出前自动纳管”。确认后完整复制到本机暂存目录，复核来源、校验目标哈希并原子提升到正式目录，同时生成环境检查结果和 `项目交接/继续项目提示词.md`。转移完成确认只结束借出操作，T9 来源必须继续保留。只有用户之后另行发布“删除移动硬盘中的该项目”指令，才进入独立清理操作；该操作复核设备身份、仓库边界、借出回执、项目编号和路径后删除 T9 旧来源，不再比较本机与 T9 的内容摘要。最后打开本机项目，按继续提示词恢复环境并继续上次未完成工作。

## 借出失败恢复

- 若本机正式项目内存在 `项目交接/借出最终化恢复.json`，运行 `repair` 继续生成交接、环境、回执和登记，不重新复制。
- 若存在 `项目交接/借出清理恢复.json`，运行 `repair` 重新验证 T9 设备、盘符、仓库、项目身份和来源摘要后，只重试删除 T9 来源与登记，不重新复制。
- 两种恢复都必须使用本机正式项目路径和已配置的 T9 仓库；设备、盘符、路径或恢复记录不一致时立即停止。

## 用户呈现

- 默认使用简洁中文呈现，并在每次结果末尾给出唯一明确的下一步。
- 脚本 JSON 是机器接口，用于可靠解析；除非用户明确要求调试信息，不直接展示原始 JSON。
- 菜单只显示中文操作名称和当前项目摘要。
- 预览只显示：将执行什么、精确来源和目标、不会删除什么、阻断项、确认方式。
- 成功结果只显示：项目名称、正式位置、校验结果、保留的副本、下一步。
- 失败结果只显示：失败阶段、已完成内容、两份项目是否安全、恢复方法。
- 环境、敏感文件和进程等辅助信息仅在影响当前操作时展开。

## 当前版本边界

稳定版 `1.1.1` 已实现项目总览、自动纳管、继续项目、记录进度、安全暂停、事务式归还 T9 和事务式从 T9 借出。归还与借出都必须经过“预览—复制校验—独立删除指令”三个阶段。预览只扫描元数据；正式复制校验首次计算完整 SHA-256，后续扫描复用未变化文件的哈希，仅重算发生变化的文件。归还清理仍要求两端摘要未变化；借出完成后 T9 来源保持不动，只有用户另行发布删除移动硬盘项目的指令才清理 T9 旧副本，且不再因本机后续变化阻断。

`1.1.1` 只做便捷性与可靠性收口：交接报告记录真实操作结果；继续提示词可直接交给任意 AI 软件；归还清理在删除来源后状态更新失败时可轻量恢复；默认向用户显示简洁中文结果，同时保留原有 JSON 接口、四项菜单和迁移步骤。
